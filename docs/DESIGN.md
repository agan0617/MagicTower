# 關卡設計說明（3.6.1）

給改關卡、調數值的人看的。玩家看的說明在 [README.md](../README.md)，完整設計文件在 [game-design.html](game-design.html)。

本文只寫**現行版本**的規則與數字；各版本為什麼這樣改、當時量到什麼，放在最後的〈版更歷史〉。

## 目標

傳統魔塔的樂趣在**規劃**：戰鬥結果是固定的，所以「先開哪扇門、先打哪隻怪、錢花在哪裡」決定一切。

- **會玩和不會玩要有明顯差距**：亂開門、只顧眼前的玩家會卡關或分數很低；會規劃的玩家分數明顯拉開
- 每一扇門、每一個房間都要是一個取捨，不能一眼就看出「根本不用進去」
- **跨樓層規劃**：前面的決定要到後面才知道對錯（標竿是胖老鼠魔塔），量法見〈跨樓層規劃的量法〉

**平衡目標**（Ken 指定）：

| 玩家 | 通關率 | 評價分布 |
|---|---|---|
| 一般真人 | 50～70% | A 少數、B≈C |
| 高手真人 | 60～90%，且比一般高約 20 個百分點 | S 少數、A≈B、C 少數 |
| 完美 | — | 和高手有明顯差距 |

- 失敗要來自打不過怪，不是缺鑰匙卡死；前期少量失敗可以，卡關不要集中在前期
- **S 線**不用硬守高手第 94 百分位；要的是三種技能的完美玩家都打得到 S（連擊可以分數最高、但通關率最低）
- **技能個性**：見〈機制〉的技能
- **跨樓層規劃**：主目標＝高手 vs 盲高手分差 ≥50%，另有兩條護欄（見〈跨樓層規劃的量法〉）

## 設計規則（`node tools/audit.js` 會檢查）

1. **沒有白開的房間**：開門花的鑰匙，裡面至少要拿得回「鑰匙＋別的東西」
2. **沒有多餘的門**：旁邊有路繞得過去的門要拿掉
3. **NPC 不擋路**：NPC 站在凹處，不可以是唯一的通道（會說完話離開、交易完離開的例外）
4. **樓梯不當岔路**：樓梯兩側的格子不經過樓梯也要在 4 步內走得通（照步數算）。樓梯放在走廊中間時，改放旁邊的死巷；不要貼著 Boss 放，一上樓按方向鍵就會直接開打、還跳過開場劇情
5. **暗牆不在主線上**：隱藏房間是額外獎勵，不找也要能破關
6. **左右內容不重複**：牆可以對稱，但鏡射位置上不能放一樣的怪、道具、門（不然同一組選擇做兩次）。Boss 層例外
7. **免費道具每層最多 3 個**（不用付任何代價就撿得到的）。1F 的怪物圖鑑不算（見〈機制〉）
8. **回音地板不能白踩**：從樓梯只開門、不打怪就走得到的回音地板會被抓出來（這層還沒打過，回音是 0，一上樓先踩過去就沒有取捨了）

稽核把回音地板和共鳴範圍的格子都當成「要付代價的閘門」，跟門、怪一樣（規則 2、7）。Boss 層照 `MT.BOSS_FLOORS` 判斷。

另外兩條靠工具與自動玩家檢查：

- **主線自給**（`node tools/keybudget.js`）：沿主線（下樓梯→上樓梯鑰匙最少的路）逐段記帳，每層空手進來也走得到樓梯（「空手缺」要是 0）。缺鑰匙只會少開支線房間，不會卡在上樓的門前
- **Boss 前要存血**：Boss 層刻意設成「一路貪小便宜的人打不過」

## 機制

- **經驗值與等級**：打怪拿金幣和經驗值。節拍之神用經驗值換等級，越後面越貴（`MT.LEVEL`）
- **技能**（10F 打倒弦之魔女後三選一，12F 老琴師鑑定才生效；升 Lv2 要勇者 Lv12、付 50 金，升 Lv3 付 100 金）。數值在 `MT.SKILL`：

  | 技能 | 配點 | Lv1／Lv2／Lv3 | 升滿級要 |
  |---|---|---|---|
  | 鐵壁 `absorb` | 防高型、最穩 | 戰鬥時防禦 ×1.35／×1.5／×1.7，最多 +90／+120／+120；擋不了魔法 | 勇者 Lv22 |
  | 反彈 `reflect` | 血高型、中庸 | 被打的那一下彈回 72／100／380%，無視防禦 | 勇者 Lv30 |
  | 連擊 `double` | 攻高型、看技術 | 每回合多打 30%／60%／兩下 100%；滿級且攻擊 ≥ 怪物防禦 ×1.6 再爆發兩下（100%＋100%）；戰鬥時防禦只算 90% | 勇者 Lv26 |

  **技能個性**：鐵壁＝下限最高、上限最低；反彈＝中庸；連擊＝看技術、上限最高：
  - **下限**＝一般玩家用該技能的通關率：鐵壁 ≥ 反彈 ≥ 連擊、兩端差 ≥8 個百分點（`tools/report.js` 會判）
  - **上限**＝各技能「最高那一段」：高手前 10% 平均、完美玩家最高分，都要連擊最高（`tools/report.js` 會判）。不看中位數：技能表現分（見〈計分與評價〉）約等於每種技能一個固定加分，鐵壁加最多，中位數會排到連擊前面
  - 底線：沒有一種技能同時下限最高又上限最高

  模擬玩家照技能配點（`tools/sim.js` 的 BUILD／BIAS：鐵壁偏好防、連擊偏好攻、反彈偏好血），不然三種只差公式、個性拉不開
- **怪物特技**：先攻、連擊、魔法（無視防禦）、破甲（防禦只算一半）、吸血（開打前吸走目前生命的一定比例，血少時打比較划算）、夾擊（走進兩隻中間失去 1/3 生命）
- **大型怪物**：`size` 2 或 3，地圖上每一格寫同一個代碼，共用一條血
- **跟位置有關的機制**：前兩區靠開門順序，後兩區各加一種「走到哪裡要付生命」的機制，讓地圖也是走位題：
  - **第 2 區起：夾擊**（`MT.pincerAt`）：走進兩隻夾擊怪中間失去目前生命的 1/3
  - **第 3 區：回音地板 `Ec`**（`MT.echoCost`）：踩上去，這層「上一場戰鬥」的損失再扣一次，踩過就散掉。每層各記各的（`st.echo[樓層]`），所以要算的是「踩之前最後打哪一隻」。11F 兩塊、12F 兩塊（一塊在老琴師正下方）、13F 兩塊、14F 兩塊、15F 一塊，都放在要先打過怪才到得了的地方
  - **第 4 區：共鳴水晶 `rc`**（`sp: aura`，`MT.auraAt`）：周圍八格（3×3）每走進一格失去 80 生命，防禦和技能都擋不掉。牠守在路口：現在就打（魔法攻擊，剛到 16F 打要約 1200、最後只要約 400），還是每次經過付一次、等變強再回來打。16F、17F、18F、19F 各兩隻
  - 回音和共鳴付了會倒下就不走（`tooHurt`）；點地圖時整條路線要付的生命先算好，付不起直接擋下來，付得起光標變粉紫色。自動尋路先找完全不用付的路，沒有才走「付最少、再來步數最少」的那條
- **鑰匙**：銅、銀、金開同色門。
  - 商人三色都不限購；每買一把，該色下一把 ×2（`MT.KEY_RATE`）。6F、13F 兩家共用一條計數（`st.shops['keys:*']`），撿到的不算
  - 起步價（`MT.SHOPS`）：6F 銅 25／銀 125／金 250，13F 表哥八折 20／100／200。`MT.keyPrice`＝起步價×倍率^已買把數，`MT.keyPriceAt` 算再多買幾把的價格；商人 UI 標下一把價格
  - 鑰匙不能賣
  - 帳（`node tools/keycalc.js`）：撿到的鑰匙（走廊 51＋房內 53＋起手 1）照門後價值分配完，剩 39 扇銅門開不起；銀門有 1 扇（價值 700）分不到、另有 4 把銀鑰匙用不完；金門 2 扇都在真結局路線上。照門後價值買，一局只會買 4～8 把銅鑰匙，起步價每翻倍約少買一把
- **風之羽**：9F 信差鴿子給，可以飛到任何去過的樓層（落在下樓梯，1F 落在起點；B1 去過才列出來），在哪一層都能起飛
- **暗牆 `Hw`**：看起來是牆，走得過去。**裂牆 `Cw`**：要鑿子（消耗品，全塔數量比裂牆少）
- **怪物圖鑑**：1F 的道具，沒拿到之前看不到怪物能力和戰鬥代價。擋在中間走廊紅史萊姆的正上方，往樓梯一定會經過

## 計分與評價

分數＝剩餘生命＋資源折算＋技能表現分（`MT.rating`）：

- **資源折算**：通關時剩下的金幣、鑰匙、經驗值照原價換算成生命（`MT.LEFTOVER` 1）
- **技能表現分**（`MT.SKILL_SCORE`、`MT.skillScore`）：只看技能生效後的 Boss 戰——13F 鏡之騎士、15F 回音之鏡、18F 回音指揮、20F 指揮家兩個階段。每一場照「你選的技能」量一個 0～1 的表現，這場的分數＝表現 × Boss 生命 × 係數 k：

  | 技能 | 表現怎麼量（`MT.bossPerf`） | k |
  |---|---|---|
  | 鐵壁 | 每一下比沒有技能時少受幾成（魔法擋不了＝0） | 0.55 |
  | 反彈 | 彈回去的傷害佔 Boss 生命幾成（最多 1） | 0.18 |
  | 連擊 | 回合比沒有技能時少幾成 | 0.05 |

  - 打 Boss 時（`MT.step`）把打之前的生命／攻／防／技能記進 `st.boss`，評分時重算；舊存檔沒有紀錄的那幾場算 0
  - **防刷**：鐵壁、連擊的表現跟戰鬥拖多長無關。反彈多挨一下就多彈一下，所以 k × 反彈比例上限 3.8 必須小於 1（現在 0.68），多挨打一定虧
  - **係數怎麼定的**：高手和完美玩家打到這幾隻 Boss 時攻防、技能等級差不多（連擊在 20F 兩者都是回合少 75%），所以這份分數約等於「選這個技能就加一個固定分」。鐵壁原本分數最低，加最多（中位數約 7000），反彈約 3500，連擊約 700——讓三種技能的完美玩家都打得到 S，連擊的最高分仍然最高
  - 結算畫面列出明細（「剩餘生命＋資源折算＋鐵壁・Boss 戰擋傷＝總分」）；教學與技能說明不寫，玩家通關後才知道
  - 模擬玩家的 `potential` 也算這份分數：已經拿到的照算，還沒打的 Boss 用現在的能力估
- 評價門檻 `MT.RATING`：**S 19000 且要真結局／A 13000／B 8400**，其餘 C
- 門檻照驗收資料定：A＝高手通關者中位數、B＝一般通關者中位數（`tools/report.js` 不加 `--keep` 會重算）；S 定在三種技能的完美玩家都有人拿得到、高手只有少數（≤10%）拿得到的位置

## 平衡流程

改地圖或數值後的快速檢查：

```
node tools/check_reach.js      # 每一格都走得到
node tools/audit.js            # 設計規則
node tools/keybudget.js        # 主線自給
node tools/solve.js            # 新手／一般／真人型（寬度 4）／高手（beam 寬度 12）各跑一次
node tools/solve.js strong --width 4 -v   # 高手每層到達時的能力（比較快）
node tools/solve.js human --width 2 --noise 500 --runs 12   # 真人型換 12 個亂數種子，看通關率、卡在哪、分數分佈
```

| 快速檢查的玩家 | 做法 |
|---|---|
| 新手 `weak` | 有鑰匙就開門、怪挑最便宜的、祭壇只買生命 |
| 一般 `mid` | 每一步挑眼前最划算的（一步前瞻） |
| 真人型 `human` | 只知道去過的樓層；一爬上新樓層就定案，之前的決定改不回來；每個局面的評分加 ±noise/2 的亂數（判斷會失準）。寬度＝同一段肯讀檔重試幾種走法 |
| 高手 `strong` | beam search，保留多個候選局面一路比到通關（等於知道後面的樓層）；寬度 12 很慢，要快就加 `--width 4` |

**驗收**（平衡要看這個，不看快速檢查）：`tools/bench.js` 平行跑真人型的幾組玩家，`tools/report.js` 印總表、重算門檻並判各項指標。

```
node tools/bench.js --runs 64 --groups gen,pro,blind,rule --out run.jsonl   # 每組每種技能 64 局＝768 局
node tools/report.js run.jsonl [完美玩家.jsonl]
```

| 組 | 參數 | 代表 |
|---|---|---|
| 一般 `gen` | `human --width 1 --noise 2000` | 第一次玩、判斷常失準 |
| 高手 `pro` | `--width 2 --noise 500 --ahead all` | 知道整座塔（重玩過、背了地圖的人） |
| 盲高手 `blind` | 同高手，`--ahead blind` | 判斷力同高手，只看得到去過的樓層 |
| 懂規則 `rule` | 同盲高手，加 `MT_RULE=1` | 知道遊戲規則（該留一把金鑰匙、鑰匙會越買越貴、後面房間更值錢），不知道地圖 |
| 完美 `perfect` | `--width 8 --noise 300 --ahead all` | 和攻略產生器 `--human` 同一組參數 |

- `bench.js`：每局寫一行 jsonl，中斷後 `--resume` 接著跑；報表附 bootstrap／Wilson 95% 區間與同種子配對差；`--mt '{"KEY_RATE":{"y":1.5}}'` 覆蓋數值試一組設定，不用改 data.js
- 子程序預設 below-normal 優先權、8 個平行（Idle 在 P／E 混合核心的機器上會被排到 E 核，每局慢 5 倍）；機器空著時 192 局約 5 分鐘、768 局約 40 分鐘
- **樣本要夠**：技能上限每種技能約 128 局才準；只看 16～64 局就調參數等於在追雜訊。技能數值只影響用那個技能的局，所以可以只重跑改到的技能（`--skill X`），其他沿用舊數據
- 小範圍試：`--from F --top T` 只跑一段樓層；`MT_SNAP=F` 記下第一次到達 F 層的局面，給 `tools/tail.js` 從那裡接著跑

**模擬玩家要注意的地方**（模擬分數要先能打到 Ken 實玩的水準才可信）：

- 每隻怪最多算到「牠守著的東西值多少」（`potential`），守樓梯、NPC、劇情道具的才照算；不然會把每隻怪都當成遲早要打
- 看整座塔的人把金幣、經驗各算 1，不然會囤到通關
- 要知道留金鑰匙拿真結局（日記、音符各算 2500，音符還沒拿時手上留一把金鑰匙另加 2500）
- 盲高手眼中去過樓層的怪都死光了，攻防會一文不值；所以給通用先驗：每點攻／防值 `MT_FUT`（200）點生命 ×（剩餘樓層／總層數）
- 高手的鑰匙遠見（`keyFuture`）照當時價格算要不要買；盲高手／懂規則會留 2 把銅鑰匙備用，也知道越往上的房間越值錢

其他工具：`tools/rooms.js <樓層>` 印出區域與相連的門怪（設計時最常用）、`tools/show.js <樓層>` 印地圖與怪物代價、`tools/count.js` 每層鑰匙／門／寶石數量、`tools/keyuse.js` 一局每層開門／撿／買鑰匙的流向、`tools/keycalc.js` 鑰匙帳。調平衡期間的地圖改動可以先寫在 `MT.MAP_PATCH`（'樓層:x,y' → 代碼，開新局時套用），定案後直接改地圖字串。

## 目前的平衡狀態（3.6.1）

432 局驗收：鐵壁、連擊與完美玩家是 3.5.0 的 main 跑的（照 3.6.1 的係數重算分數），一般、高手的反彈是反彈 72／100% 另外跑的（`tools/bench.js --groups gen,pro --skills reflect --runs 64 --mt …`）；完美反彈還是 76／105% 的數字，沒重跑。這次沒跑盲高手、懂規則（Ken 指定），跨樓層規劃的三個指標沒量。3.6.0 只換背景音樂，不影響這份數字。

## 跨樓層規劃的量法

用三組判斷力相同的高手（上面驗收表的高手、盲高手、懂規則），只差「知道多少」。差距一律 (高−低)/高，沒過的局分數算 0：

- **主目標**：高手 vs 盲高手的分差 ≥50%
- **護欄 1**：高手 vs 懂規則的差距 ≤34.3%——增量不能只來自背地圖（34.3%＝基準 29.3%＋5 個百分點，基準的量法見〈版更歷史〉3.2.74）
- **護欄 2**：盲高手通關率 ≥ 一般——判斷力更好的人不該因為「不知道」死更多

`tools/bench.js` 另有 `pro_nokf`（高手但關掉鑰匙遠見 `MT_KF=0`）、`pro_nokf_nokeep`（再關掉留金鑰匙 `MT_KEEP=0`）兩組，用來拆解差距的來源。計畫全文與各方向的評估在 [strategy-depth-plan.md](strategy-depth-plan.md)。

**目前的理解**：差距大半是結構性的——「知道後面每一隻怪長什麼樣」對攻防配點的價值，改幾隻怪或鑰匙價格動不太了；鑰匙要真的稀缺（硬限量、拿掉房內鑰匙）才拉得開，但那會讓一般玩家卡在缺鑰匙。各次實驗的數字見〈版更歷史〉的 3.2.74、3.3.0、3.4.0。
