# 策略深度改版計畫（strategy-depth 分支）

目標：讓這座塔需要**跨樓層規劃**（像胖老鼠魔塔那樣，前面樓層的決定要到後面才知道對錯），
同時維持原本的平衡目標。分支 `strategy-depth`，從 3.2.73 分出（已併入 main 的 0c52bd8）。

---

## 一、為什麼現在策略性不夠

結論：**決策幾乎都在同一層內就算得完**。

證據：DESIGN.md 記錄的真人型模擬——不加判斷失誤時，只看得到去過樓層的玩家分數跟知道整座塔的高手差不多。
難度來自「算錯」，不是「沒預想到後面」。

四個原因：

1. **鑰匙不稀缺**：黃鑰匙地上 96 把、黃門 158 扇，但呱呱商人不限量賣、一把 8～10 金，全塔金幣上萬。
   高手模擬一局開 120 扇黃門、撿 96 把、買 19 把，買鑰匙只是小錢。加上 9F 風之羽隨時能回頭。
2. **稽核規則刪掉了「錯的選項」**：規則 1（沒有白開的房間）、2（沒有多餘的門）、6（左右不重複）
   讓選項都不吃虧，玩家只需要決定順序，不必決定要不要。
3. **所有資源都換得到生命**：金幣→祭壇、鑰匙→賣回、經驗→等級，剩下的還 ×1.3 算分。
   都換成同一種貨幣後，「每步挑最划算的」就接近最佳解。高手到 14F 有 3787 血、到 20F 還帶 4222 金，後期沒有壓力。
4. **3.1 加的機制是線性扣血**：夾擊、回音地板、共鳴水晶只多一道算術題。DESIGN.md 量過：
   沒讓真人型多卡任何一層，只讓高手少 400～1600 分。

## 二、目標

### 原本的平衡目標（必須維持）

| 項目 | 目標 | 3.2.73 現況（舊模擬器） |
|---|---|---|
| 一般真人通關率 | 50～70% | 約 67% |
| 一般真人評價 | A 少數、B≈C | B 門檻＝一般中位數 |
| 高手真人通關率 | 80～95% | 約 84% |
| 高手真人評價 | S 少數、A≈B、C 少數 | S≈高手前 6%（要真結局）、A＝高手中位數 |
| 高手比一般高約 20 個百分點 | ≈ +20 | +17（差一點） |
| 完美玩家和高手拉開差距 | 明顯 | 完美 24364 |
| 技能下限：鐵壁 ＞ 反彈 ＞ 連擊，相鄰差 ≥5 個百分點 | | 81% ＞ 68% ＞ 51% |
| 技能上限：連擊 ＞ 反彈 ＞ 鐵壁，相鄰差 ≥5% | | 22301 ＞ 19189 ＞ 17754 |
| 卡關不集中在前期 | 前期少量失敗可接受 | — |

評價門檻（3.2.73）：S 20500＋真結局／A 15600／B 5650。

### 新增目標

**跨層規劃差距 ≥15%**：高手參數（寬度 2、noise 500）跑兩組，一組知道整座塔（`--ahead all`），
一組判斷力相同但看不到沒去過的樓層（`--ahead blind`），比較平均分數（沒過算 0）。

前提：跨層的失誤應該**扣分而不是卡死**，不然一般玩家的通關率會掉下去。

## 三、策略

讓跨層規劃成立要同時有三件事：

1. **有一樣帶得走、又不夠用的資源**
2. **現在的決定要到後面才看得出對錯**
3. **玩家事先猜得到後面需要什麼**（不然只是坑第一次玩的人）

塔裡已經有一個現成的例子：**為了拿失落的音符要留一把金鑰匙**。三件都符合，
而且模擬玩家要特別教才學得會（校準紀錄的第 ③ 點），證明這種設計確實拉得開差距。這次是把同樣的做法擴大。

四個方向，照效果排：

| 方向 | 做法 | 怎麼產生跨層規劃 |
|---|---|---|
| **A. 鑰匙越買越貴**（主要） | 兩個商人合計，每買一把該色鑰匙，之後每把再貴一點（`MT.KEY_STEP`） | 前面亂開門，後面就得花大錢補；後面樓層的房間比較值錢（區域數值 1→4 區遞增），會規劃的人把鑰匙留給後面 |
| B. Boss 後會消失的東西 | 2～3 個 NPC 或交易在區域 Boss 打倒後離開，台詞含蓄暗示 | 逼玩家在打 Boss 前決定要清掉什麼 |
| C. 破防門檻 | 後面樓層放一群防禦剛好卡在某個值的怪 | 祭壇買攻還是買防，要看預計多快到那層 |
| D. 可以留著用的消耗品 | 各層裂牆後面的獎勵價值拉開 | 鑿子「現在敲還是留到後面」變成跨層取捨 |

**A 選「漲價」而不是「限量」的原因**：限量會讓亂花鑰匙的人在主線門前被卡死、直接過不了關，
一般玩家的通關率會崩。漲價永遠買得到，只是貴——失誤變成扣分，符合前提。
這也是 3.2.37 祭壇越買越貴、Ken 認可過的同一招。

### 模擬器改動（`tools/sim.js`）

- **`ahead='blind'`（盲高手）**：判斷力跟 `'all'` 一樣（金幣經驗估價、真結局估價、會找暗牆、怪值不值得打），
  但怪物傷害只算去過的樓層，也不知道要留金鑰匙拿音符。和 `'all'` 的分數差＝「知道後面樓層」值多少。
- **老手的鑰匙遠見估價**（`doorValues`／`keyFuture`，只用在 `'all'`）：原本模擬玩家把每把鑰匙當固定價，
  不會為了後面更值錢的門省鑰匙，鑰匙變稀缺後就量不出差距。現在：
  - 開局地圖上，每扇門的價值＝門後那塊（其他門與牆擋住）道具的總值；在下樓梯→上樓梯最少鑰匙那條路上的門＝主線，值 4000
  - 手上鑰匙的價值＝後面樓層的門照價值排序，後面撿得到的鑰匙先拿去開最好的那幾扇，手上這幾把接著開下一批
  - 商人買得到時，最多值「目前賣價 ×5」
  - `MT_KF=0` 可以關掉，回到原本的固定價

### 量測工具

- **`tools/bench.js`**：一般／高手／盲高手三組平行跑，印出目標表各項、跨層差距、高手比一般高幾個百分點。
  每局跑完立刻寫進 jsonl，中斷後加 `--resume` 接著跑。
  - 一般＝`human --width 1 --noise 2000`；高手＝`human --ahead all --width 2 --noise 500`；盲高手＝高手參數加 `--ahead blind`
- **`tools/keyuse.js`**：印一局每層開門、撿、買鑰匙的數量，用來看鑰匙流向。

### 跑模擬的資源限制

- **不能吃滿 CPU**：要留給 Telegram bot 和其他工作。平行數上限 10、程序設成低優先權（之前 19 個平行跑時把電腦拖慢）。
- 單局約 30 秒（單獨跑時）；一輪 180 局（每組每種技能 20 局）在 10 個平行下約 15～20 分鐘。
- 背景工作上限設 2 小時，避免跑到一半被停掉。

## 五、風險與對策

| 風險 | 對策 |
|---|---|
| 鑰匙變貴讓一般玩家卡死 | 用漲價不用限量；每層上樓的主線要有足夠的免費鑰匙（稽核規則「主線鑰匙要夠」） |
| 盲高手的落差主要來自別的因素（例如不知道最終魔王、不知道留金鑰匙），而非一般的跨層規劃 | 先看基準的落差組成；必要時調整量法，只量「後面樓層內容」本身 |
| 小樣本（每組 20 局）雜訊大 | 調整期用 20 局，定案前用 60 局驗收 |
| 方向 B 模擬量不出效果（模擬玩家讀不懂台詞） | 方向 B 是給真人的，模擬只用來確認通關率沒被打壞 |
| main 同時有別的 session 在改 | 每個階段開始前先把 main 併進來 |
