# 策略深度改版計畫 v2（strategy-depth 分支）

目標：讓這座塔需要**跨樓層規劃**（前面樓層的決定要到後面才知道對錯），同時維持原本的平衡目標。
分支 `strategy-depth`，從 3.2.73 分出（已併入 main 的 0c52bd8）。

v2 改了什麼（2026-10-05 複審）：
1. **量尺重定義**——基準試跑的高手 vs 盲高手差距已約 98%，原目標「≥15%」在動手前就達標，改成量「改版帶來的增量」並加兩道護欄
2. **先驗證盲高手這把尺**——試跑裡盲高手通關率（65%）低於一般玩家（79%）、11 局卡 20F，判斷力更好卻死更多，不是塔有坑就是模擬器有問題，沒釐清前量出來的全是雜訊
3. **方向 A 補效果量估算與配套**——現況買鑰匙總共花約 190 金（全塔約 12,400 金），單靠漲價要漲到很陡才咬得到人；改成供給、需求、顯示三面一起做
4. **方向 C 升到第二順位、B 降到最後**——C 模擬量得到、是魔塔跨層規劃的正統來源；B 模擬量不到又有「錯過就沒了」的挫折風險
5. **驗收樣本 60 → 128**——DESIGN.md 自己記的教訓（前 10% 平均要 128 局才準），v1 自相矛盾
6. **流程修正**——機制全部用旗標包起來、模擬器先凍結再量基準（避免再被中途改動污染）；bench.js 預設平行數調低、設低優先權；v1 說「已備好」的方向 A 程式其實不在 repo 裡，要重寫

## 一、為什麼現在策略性不夠

結論：**決策幾乎都在同一層內就算得完**。

證據：DESIGN.md 記錄的真人型模擬——不加判斷失誤時，只看得到去過樓層的玩家分數跟知道整座塔的高手差不多。
難度來自「算錯」，不是「沒預想到後面」。

四個原因：

1. **鑰匙不稀缺**：黃鑰匙地上 96 把、黃門 158 扇，差 62 把；但呱呱商人不限量賣、一把 8～10 金，全塔金幣約 12,400。
   高手一局撿 96 把、買 19 把、開約 115 扇——**已經有 40 多扇黃門沒開**，可是「不開哪幾扇」是看當層划不划算決定的，不是為了後面省下來的。
   買鑰匙總共只花約 190 金，不到全塔金幣的 2%。9F 風之羽讓回頭補救也免費。
2. **稽核規則刪掉了「錯的選項」**：規則 1（沒有白開的房間）、2（沒有多餘的門）、6（左右不重複）
   讓選項都不吃虧，玩家只需要決定順序，不必決定要不要。
3. **所有資源都換得到生命**：金幣→祭壇、鑰匙→賣回、經驗→等級，剩下的還 ×1.3 算分。
   都換成同一種貨幣後，「每步挑最划算的」就接近最佳解。高手到 14F 有 3787 血、到 20F 還帶 4222 金，後期沒有壓力。
4. **3.1 加的機制是線性扣血**：夾擊、回音地板、共鳴水晶只多一道算術題。DESIGN.md 量過：
   沒讓真人型多卡任何一層，只讓高手少 400～1600 分。

一個現成的反例證明做法可行：**為了拿失落的音符要留一把金鑰匙**（3.2.55 校準紀錄第 ③ 點）——帶得走、不夠用（金鑰匙全塔限 2）、事先猜得到（有金門就有金鑰匙的用處）。
金鑰匙限量能成立，是因為**金門全部不在主線上**；黃門在主線上，所以黃鑰匙不能限量只能漲價（見〈三、策略〉）。

## 二、目標

### 原本的平衡目標（必須維持）

| 項目 | 目標 | 3.2.73 現況（舊模擬器） |
|---|---|---|
| 一般真人通關率 | 50～70% | 約 67% |
| 一般真人評價 | A 少數、B≈C | B 門檻＝一般中位數 |
| 高手真人通關率 | 80～95% | 約 84% |
| 高手真人評價 | S 少數、A≈B、C 少數 | S≈高手前 6%（要真結局）、A＝高手中位數 |
| 高手比一般高約 20 個百分點 | ≈ +20 | +17（差一點） |
| 完美玩家和高手拉開差距 | 明顯 | 完美 24364 |
| 技能下限：鐵壁 ＞ 反彈 ＞ 連擊，相鄰差 ≥5 個百分點 | | 81% ＞ 68% ＞ 51% |
| 技能上限：連擊 ＞ 反彈 ＞ 鐵壁，相鄰差 ≥5% | | 22301 ＞ 19189 ＞ 17754 |
| 卡關不集中在前期 | 前期少量失敗可接受 | — |

評價門檻（3.2.73）：S 20500＋真結局／A 15600／B 5650。

### 新增目標（v2 重定義）

三組高手參數相同（寬度 2、noise 500），只差「知道多少」：

| 組 | 看得到什麼 | 代表誰 |
|---|---|---|
| 高手 `--ahead all` | 整座塔 | 重玩過、背了地圖的人 |
| 盲高手 `--ahead blind` | 只有去過的樓層，判斷力同高手 | 第一次玩、但很會算的人 |
| （v2 新增）懂規則的盲高手 `--ahead blind --rule` | 同盲高手，但知道遊戲規則（鑰匙會漲價、後面房間更值錢、Boss 後 NPC 會走），不知道地圖 | 第一次玩、有讀商人台詞與說明的人 |

量三個數字（分數沒過算 0，用平均，**差距一律寫成 (高−低)/高**，v1 的 (高−低)/低 會把差距灌水）：

1. **主目標：高手 vs 盲高手差距 ≥50%**（2026-10-06 Ken 改定為絕對值；v2 原本寫「比基準多 15 個百分點」，尺修好後基準是 37.6%，兩種算法差不多，用絕對值比較直觀）。
2. **護欄 1：不坑第一次玩的人**——「高手 vs 懂規則的盲高手」差距不能比基準大超過 5 個百分點。這條守的是策略前提 3「玩家事先猜得到後面需要什麼」：差距若全開在這裡，代表只是地圖記憶題。
3. **護欄 2：失誤扣分不卡死**——盲高手通關率 ≥ 一般玩家通關率。判斷力更好的人不該死得更多；低於一般就是塔在用「不知道」殺人。

`--rule` 模式的實作（`tools/sim.js`）：不用 `doorValues`／`keyFuture`（那要看地圖），改用不看地圖也算得出的先驗——
手上鑰匙的價值＝「下一區黃門房間的平均價值」（照 `ZONE_VALUES` 算）與「商人下一把的價格×5」取高者；知道 Boss 後會消失的 NPC（方向 B）；知道金鑰匙該留一把。
這樣「懂規則但沒背地圖」的人能做到的規劃就全在裡面了。

## 三、策略

讓跨層規劃成立要同時有三件事：

1. **有一樣帶得走、又不夠用的資源**
2. **現在的決定要到後面才看得出對錯**
3. **玩家事先猜得到後面需要什麼**（不然只是坑第一次玩的人）

四個方向，v2 照「模擬量不量得到」與「效果／成本」重排：

| 順位 | 方向 | 做法 | 怎麼產生跨層規劃 | 模擬量得到？ |
|---|---|---|---|---|
| 1 | **A. 黃鑰匙變稀缺**（主要） | 見下節，供給／需求／顯示三面 | 前面亂開門，後面就得花大錢補；後面樓層的房間比較值錢（區域數值 1→4 區遞增） | 量得到（三組都會反應） |
| 2 | **C. 破防門檻** | 第 3、4 區各放一群防禦卡在同一個值的怪（例如 3 區 df 恰好讓「沒買第 N 次祭壇攻擊」的人打不動） | 祭壇買攻還是買防、買幾次，要看預計多快到那層；這是傳統魔塔跨層規劃的主要來源 | 量得到（`MT.calc` 直接反應） |
| 3 | **D. 可以留著用的消耗品** | 各層裂牆後面的獎勵價值拉開（前期裂牆後放普通寶石、後期放裝備級獎勵） | 鑿子「現在敲還是留到後面」變成跨層取捨 | 量得到（鑿子已有估價） |
| 4 | B. Boss 後會消失的東西 | 2～3 個 NPC 在區域 Boss 打倒後離開，台詞含蓄暗示 | 逼玩家在打 Boss 前決定要清掉什麼 | 只有 `--rule` 組量得到；主要是給真人的 |

### 方向 A 怎麼做（v2 展開）

**效果量先算清楚**：現在買鑰匙一局 19 把、約 190 金。若只做「每買一把漲 N 金」，19 把的總價＝190＋N×171。N＝2 多花 342 金（全塔 3%，不痛不癢）；N＝5 多花 855 金；要讓第 19 把貴到跟 11F 祭壇一次（約 120～400 金）一樣，N 要到 10～20，第 19 把 200～400 金——真人看到「一把鑰匙 400 金」會覺得莫名其妙。
**單靠漲價要很陡才咬得到人，而陡了就不合理**，所以三面一起做，每一面都溫和：

| 面 | 做法 | 旗標 | 預設值（待調） |
|---|---|---|---|
| 需求 | 兩個商人合計，每買一把該色鑰匙，下一把貴 `KEY_STEP` 金（不會因為上樓或換商人重置） | `MT.KEY_STEP = { y, b, r }` | y 3／b 10／r 0（金鑰匙已限量） |
| 供給 | 第 3、4 區地上的黃鑰匙減少（96 → 約 84；每層減 1～2 把），減掉的換成同區寶石，房間價值不變 | 改 `js/data.js` 地圖，稽核規則「主線鑰匙要夠」照跑 | 11F～19F 各 −1～−2 |
| 顯示 | 商人對話框標「現價 N（每買一把 +M）」；6F 商人初次見面台詞提一句「越買越貴」。這是策略前提 3，**沒有這面就是在坑人** | `info_frog`／`info_buyer` 文案 | — |

配套：

- **稽核規則 1 要改**：「開門花的鑰匙，裡面至少要拿得回鑰匙＋別的東西」是用「一把鑰匙＝固定價」算的。鑰匙變稀缺後，門後價值要用**該區的鑰匙機會成本**比（例如 3 區一把黃鑰匙算 `KEY_STEP` 累進後的典型價格）。不改的話稽核不是全過就是全不過。`tools/audit.js` 加 `--keyvalue` 參數或讀同一組旗標。
- **表哥的角色不變**：13F 表哥仍比 6F 便宜（3.2.59 Ken 指定），漲價是兩人共用計數，所以「飛回 6F 買」永遠不划算。收購價（b 25／r 50）**不漲**，免得出現買低賣高。
- **8F 小偷**維持便宜且不限量；若方向 B 讓他在 10F Boss 後離開，等於自然形成「前期便宜貨、後期貴」的取捨，兩個方向互補。
- **不動金鑰匙**：限 2 已經是成立的跨層設計，別碰。

**A 選「漲價」不選「限量」的理由不變**：黃門在主線上，限量會讓亂花的人卡死；漲價永遠買得到，只是貴。金鑰匙能限量是因為金門全不在主線（規則 5 的延伸）。

### 方向 C 怎麼做

- 挑 2～3 種第 3、4 區會重複出現的怪，把防禦設在「照標準路線到那層時攻擊力剛好差 3～5 點」的位置；買過一次祭壇攻擊的人剛好過線。
- **要跟技能平衡一起看**：連擊的爆發條件是攻擊 ≥ 怪防 ×1.6，已經是一種破防門檻；鐵壁的配點偏防。C 會直接拉動三種技能的上下限，調完每種技能各跑一輪（`--skill X`）。
- 怪物圖鑑拿到才看得到數值，所以 C 對第一次玩的人是「上一層看到這種怪、記住下一層會更多」的題，符合前提 3。

### 方向 B 的邊界

- 只動**非主線、非真結局**的 NPC：候選 8F 小偷、7F 鐵匠（10F Boss 後離開）、14F 學徒（15F Boss 後離開）。
- 台詞要含蓄但要有（「這裡快不安全了」），不能劇透真結局或道具用途（Ken 定過的不劇透原則）。
- 攻略產生器 `tools/guide.js` 要加「Boss 前要先辦的事」一節。
- 模擬只用 `--rule` 組與通關率確認沒打壞，不拿它當主目標的證據。

### 模擬器改動（`tools/sim.js`）

已在分支上（236202e）：

- **`ahead='blind'`（盲高手）**：判斷力跟 `'all'` 一樣（金幣經驗估價、真結局估價、會找暗牆、怪值不值得打），
  但怪物傷害只算去過的樓層、不用 `keyFuture`、也不知道要留金鑰匙拿音符。
- **老手的鑰匙遠見估價**（`doorValues`／`keyFuture`，只用在 `'all'`）：每扇門的價值＝門後那塊道具的總值；
  主線門值 4000；手上鑰匙的價值＝後面樓層的門照價值排、後面撿得到的先開最好的、手上的接著開下一批；商人買得到時最多值賣價×5。

v2 要補：

- **`--rule`**（懂規則的盲高手）：見〈二、新增目標〉。
- **鑰匙估價要跟漲價連動**：`kv` 與 `keyFuture` 裡的「賣價×5」要改讀**下一把的價格**（`MT.keyPrice(st, c)`），不然漲價後模擬玩家還是照 10 金估。
- **`keyuse.js` 加印**：每層買鑰匙時的單價、鑿子用在哪層。

### 量測工具（`tools/bench.js`）

v2 要修的：

- **`--jobs` 預設 18 → 8**，留 CPU 給 Telegram bot 和其他工作（v1 寫上限 10，程式預設卻 18）。
- **子程序設低優先權**：`spawn` 後 `os.setPriority(p.pid, 19)`（Node 內建，Windows 對應 IDLE 優先權），不用再靠外面包 `start /low`。

- 仍然每局寫 jsonl、`--resume` 接著跑。

## 五、風險與對策

| 風險 | 對策 |
|---|---|

## 八、之後的三個維度（2026-10-06 Ken 指定寫下，鑰匙這輪做完再排）

鑰匙那條做的是基礎建設：資源先有稀缺性，下面三個維度才有意義。它們各自讓一種決定「要到後面才知道對錯」，量法都用〈二〉的三組高手與三個指標；**每一個都要配一個第一次玩也猜得到的訊號**，不然只是記憶題，護欄 1 會抓出來。建議順序：**攻防門檻 → 回頭的成本與回報 → 路線順序**（前兩個調現有的怪與道具表就做得到，稽核規則不用動；第三個要加地圖結構、改引擎與稽核，工程最大）。每加一個維度，平衡目標表（一般 50～70、高手比一般高約 20、技能上下限順序）都要重跑，各估一到兩個晚上的機器時間；排在 3.4、3.5。

### 8.1 攻防配點：讓「買攻還是買防」有對錯

成立條件：怪物數值要有**門檻**而不是平滑曲線。現在怪的防禦落在玩家攻擊力附近的連續帶上，多買一次攻擊只是少打一回合，兩邊都過得去。

- 每區放一到兩種**高防低血**的門檻怪（石像守衛 `st`、水晶魔像 `cg` 已經是），防禦設在「照標準路線到那層時攻擊力剛好差 3～5 點」：差一點就打不動或打得很痛，過線一刀。
- 同一區再放一種**高攻低防**的怪（連擊、先攻型），讓防禦也有門檻：防禦夠只掉一點點，不夠就被連擊打到半殘。
- 兩種怪數量要夠多，而且**在上一層先露臉一隻**，玩家在圖鑑看得到數值，才能在這層的祭壇決定「下一層那群石像，攻擊要再高 5 點」——這就是跨層。
- 三種技能已有配點傾向（鐵壁堆防、連擊堆攻），門檻怪會自然拉開技能差異；要重跑技能上下限確認順序沒亂。
- 教訓：3.2.74 的 C1 只把兩種怪各變硬一點、沒做「上一層露臉」，三組估價方式一樣所以量不出差距；門檻必須配合可預見性才會進到懂規則值。

### 8.2 何時回頭：讓「等變強再回來」划算但有成本

現在 9F 風之羽之後回頭免費，回音地板、共鳴水晶只是「現在付還是等一下付」的小題。

- **回頭要有代價**：風之羽改成有次數，或只能飛到錨點層（祭壇、商人、節拍之神所在層），其餘用走的。
- **回頭要有回報**：每區放一兩個「現在打掉一千血、兩層後拿到裝備只掉兩百」的守寶怪，寶物要值得（裝備、大量金幣）。守寶怪用**同一種外型**，圖鑑看得到，玩家會記住「這隻先別打」。
- **樓層之間要有只有回頭才接得上的連結**：下一層撿到的鑰匙、鑿子，對應上一層沒開的門、沒敲的裂牆。鑿子與裂牆已經是這個設計，但裂牆後的獎勵價值沒拉開（〈三〉的方向 D）。
- 量法：高手知道兩層後有裝備會先跳過守寶怪，盲高手會當下打或永遠不打；懂規則值靠「守寶怪看得出來」。

### 8.3 路線順序：讓「先開哪邊」有代價

現在每層幾個房間各一道門，順序幾乎不影響結果。能製造順序取捨的結構：

- **單向或一次性的通道**：踩了就關的門、推開就不能回頭的機關，走錯邊要繞遠路或付血。
- **互斥獎勵**：同一層兩個房間用同一把專屬鑰匙或同一位 NPC 的交易，拿了這邊就沒那邊（技能三選一是這種，但只有一次）。
- **資源在 A 區、需求在 B 區**：祭壇在左半邊、金幣在右半邊、上樓梯在中間，要決定先去哪邊、回不回頭。
- **Boss 後消失的 NPC**（〈三〉的方向 B）：打 Boss 前要先清掉該交易的；模擬玩家會立刻成交所以量不到，只能給真人，台詞要含蓄暗示且不劇透。
- 量法：模擬玩家對這類結構天生會算，主目標會動；懂規則值要看 NPC 台詞與機關提示有沒有讓不背地圖的人猜得到。
- 工程：單向門與一次性機關要加圖塊與引擎邏輯、稽核規則 2（多餘的門）與 4（樓梯不當岔路）要重新定義，攻略產生器也要認得。
